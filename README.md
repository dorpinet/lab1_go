Практична робота № 1: **Базові конструкції, структури даних та конкурентність у Go**.

Консольна утиліта для моніторингу доступності HTTP-ресурсів. Показує еволюцію рішення:
від послідовної перевірки до конкурентної (горутини, `sync.WaitGroup`, канали) та порівнює швидкодію обох підходів.

## Запуск

Потрібен **Go 1.22+**.

```bash
git clone https://github.com/dorpinet/lab1_go.git
cd lab1_go
go run .
```

Перевірка на стан гонитви:

```bash
go run -race .
```

> На Windows для прапорця `-race` потрібен C-компілятор (gcc, наприклад MinGW-w64) та `CGO_ENABLED=1`.

## Реалізовані рівні

### Рівень 1. Базовий: структури, методи, послідовний моніторинг

- структура `Result` (URL, статус, тривалість, помилка);
- інтерфейс `Checker` з методом `Check(url string) Result`;
- `HTTPChecker` із налаштовуваним таймаутом на базі `http.Client`;
- точний замір часу через `time.Now()` / `time.Since()`;
- послідовний прогін по списку з 5 адрес, серед яких одна завідомо неіснуюча.

![Рівень 1](screenshots/Screenshot_2026-10-22_180358.png)

### Рівень 2. Конкурентний: горутини, WaitGroup, Mutex

- кожен URL перевіряється в окремій горутині;
- адреса передається в горутину аргументом (без захоплення змінної циклу);
- `sync.WaitGroup`: `Add(1)` до запуску горутини, `defer Done()` всередині;
- спільна статистика захищена `sync.Mutex`.

![Рівень 2](screenshots/Screenshot_2026-10-22_181617.png)

### Рівень 3. Просунутий: канали

- горутини надсилають `Result` у буферизований канал замість зміни спільних лічильників;
- окрема горутина-координатор чекає `wg.Wait()` і закриває канал через `close()`;
- головна горутина вичитує результати через `for res := range results` та веде статистику сама, тому м'ютекс більше не потрібен;
- виводиться підсумковий звіт і порівняння часу послідовного та конкурентного режимів.

## Результат порівняння швидкодії

За підсумками запуску з Рівня 3 (5 адрес): конкурентна перевірка зайняла **182 мс** проти **1,064 с** у послідовному режимі, тобто швидше приблизно в **5,8 раза**. У конкурентному режимі загальний час майже дорівнює часу найповільнішого запиту, а не сумі всіх запитів.

## Технології

Go 1.22+, стандартна бібліотека: `net/http`, `sync`, `time`, `fmt`.
